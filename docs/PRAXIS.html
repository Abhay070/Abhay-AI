Praxis
Field Manual · v1.0.0

An AI that argues back and then builds the thing

Praxis is a personal AI assistant you run yourself. It takes the same shape as ChatGPT or Claude — you type, it streams back — but it is built on a different instruction: respect the person, interrogate the idea. It has ten operating modes, remembers what matters about you, calls real tools instead of guessing, and runs entirely on your own machine for nothing.

01

The idea

Most assistants are tuned to be agreeable. Ask whether your business idea is good and you will hear what is exciting about it. That is pleasant and almost useless — the failure mode of a helpful assistant is telling you what you hoped to hear.

Praxis is built the other way round. Its core instruction says that agreement it did not actually reach is a failure, not politeness; that weak assumptions get named; that if there is a better approach it should argue for it. The identity is compiled into the system prompt on every single request, so this is not a mode you remember to switch on — it is the baseline.

Don't just answer. Think. Challenge. Build. Verify. Execute.

The operating loop, from the specification

Four commitments follow from that, and each one shows up as a concrete mechanism rather than a promise in a prompt:

  • It says what it doesn't know. Knowledge is classified as known, uncertain, current, provided or inferred — and it is told never to blur those categories or present an assumption as a fact.
  • It never claims work it didn't do. It cannot say it searched, ran, read or verified something unless a tool actually returned. If a tool fails, it reports the failure.
  • It computes rather than predicts. Arithmetic goes to a calculator, current facts go to a search, code gets executed.
  • It ends with a move. Insight, then recommendation, then the next action — rather than three paragraphs of information and a summary of the paragraphs.
02

How a turn works

Everything between pressing Enter and reading an answer, in order. Stages 4 and 5 can repeat: the model asks for a tool, gets the result, and continues.

01
Compose
Core identity, the active mode, and the current date are assembled into one system prompt.
02
Recall
Memories are scored against the recent conversation; the most relevant dozen join the context.
03
Stream
The backend answers token by token. Text reaches your screen as it is produced.
04
Intercept
A tool call is caught mid-stream and held back, so raw syntax never reaches you.
05
Execute
The tool runs. Its result is fed back and the model continues from there.
06
Record
The answer is saved with its mode, backend, tool count and elapsed time.

Stages 4–5 loop up to six times per turn, then stop — a ceiling so a confused model cannot spin forever burning tokens.

What that looks like

one turn, standard mode 
you › how many pixels in a 4K frame, and is that 4× 1080p?

  ∑ calculate   3840*2160                        ✓
  ∑ calculate   (3840*2160)/(1920*1080)          ✓

praxis › 8,294,400 pixels. And yes — exactly 4×, because 4K
doubles both dimensions rather than one.

2.1s · 2 tool calls · 0 guesses

The two calculations are real. A language model asked that question directly will often produce a number that looks right and isn't, because it is predicting plausible digits rather than multiplying. Every tool call is shown in the interface as it happens, and you can expand any of them to see exactly what came back.

03

Ten modes

A mode is a behavioural overlay, not a different model — so switching is instant and costs nothing. The core identity holds throughout; the mode sharpens it for the work in front of you.

ModeWhat changesReach for it when
◈ Standard Nothing added — the core identity on its own, adapting to what you bring. Default. Most conversations.
→ Direct Conclusion first, under 150 words, no preamble or closing pleasantries. Says the uncomfortable thing in sentence one. You're in a hurry, or you want the verdict without the cushioning.
▲ Founder Interrogates commercially: who specifically needs this, what do they do instead, why now, what's the moat, what kills it, what's the cheapest experiment. Any business idea, before you write code.
⊗ Reality Check Structured teardown across ten headings, ending in a verdict: pursue, pursue with changes, test first, or drop it. A decision you keep going back and forth on.
⚒ Build Requirements to architecture to code to deployment. Recommends one stack and defends it instead of listing four. Turning an idea into something that actually runs.
◇ Research Searches before answering, names sources, checks dates, surfaces disagreement, marks anything unverified. Anything current, contested, or that you'd need to cite.
◎ Teacher Builds from what you already know, one idea at a time, concrete example before the general rule, and names the common misconception. Learning something properly rather than getting an answer.
? Socratic Refuses to give the answer. Asks the one question that exposes the gap. Gives in if you explicitly ask it to. You want to actually understand it, not be told it.
✓ Exam Questions one at a time, honest marking, difficulty that adapts to your streak, and a report on what's weak. Revision, or finding out what you don't actually know.
▤ Executive Brief Situation, problem, options with costs, a recommendation it commits to, and the first action. Under 350 words. Someone has to decide something today.
Design note

Modes are text appended to the system prompt, which is why they are free and instant. The source specification runs to several thousand words; sending all of it every turn would cost roughly 4,000 tokens per request and, worse, spread the model's attention across a hundred instructions of which maybe eight apply. Compiling it into an always-on core plus a mode overlay gets the same behaviour at about a quarter of the tokens.

04

Nine tools

Tools are what separate an assistant that talks from one that does. Praxis decides on its own when a tool would materially improve the answer, calls it, and shows you the call.

ToolDoesStatus
∑ calculate Exact arithmetic. Parses to a syntax tree and walks it — never eval(), which on model output is a remote-code-execution hole. on
◷ current_time The real date and time, in any offset. Closes the failure where a model confidently answers "what day is it" from training data. on
⌕ web_search Four interchangeable backends — DuckDuckGo needs no key at all; Brave, Tavily and your own SearXNG are drop-in alternatives. on
⇲ web_fetch Reads a page as clean text. Scripts and styling stripped, whitespace collapsed, truncated with the truncation declared. on
▤ read_file Full text of anything you upload or drag in — code, CSV, Markdown, JSON, logs, PDF. on
◆ remember Stores a durable fact about you, in one of six categories, for every future conversation. on
◇ recall Searches what it knows about you, for something not already in context. on
◌ forget Deletes a memory — but only on an unambiguous single match, so a vague instruction can't wipe several. on
▶ run_python Real execution in a subprocess with a hard timeout. Genuinely useful for analysis and genuinely dangerous, so it ships disabled. off by default
On code execution

What the isolation gives you, stated plainly: a separate process, a hard timeout, output truncation, a temporary working directory. What it does not give you: a real sandbox. The subprocess runs as your user and can import anything installed and read your files. If you need real isolation, run Praxis in a container. Don't enable this on a machine holding anything you'd mind losing.

05

Memory

Praxis stores keyed facts, not transcripts. "Prefers Rust for systems work" is a memory. "Asked about lifetimes on Tuesday" is not.

The model decides what is worth keeping, which is the right design — a rule that stores everything produces a memory nobody can trust, and one that stores nothing produces an assistant that asks your name every morning. What you keep is entirely yours to audit: open the memory panel, edit any fact in place, delete one or all of them. A current instruction always overrides a remembered preference.

CategoryHoldsExample
factStable things true about youBased in Bangalore, works in IST
preferenceHow you like things doneWants code with comments, no emoji
projectWhat you're buildingBuilding Praxis, a personal AI
goalWhat you're working towardWants to understand transformers properly
decisionChoices already made, so they aren't relitigatedChose SQLite over Postgres for v1
skillWhat you already know, so it doesn't over-explainStrong in Python, new to Rust

Why recall is deliberately simple

Relevance is keyword overlap with the recent conversation, plus a small bonus for memories that have proved useful before. No embeddings, no vector database.

That is a considered choice rather than a shortcut. At personal scale — hundreds of memories, not millions — lexical overlap is roughly as accurate as embeddings and has one decisive advantage: you can look at a memory and understand why it surfaced. A memory system whose behaviour is inexplicable is one you stop trusting, and an untrusted memory is worse than none. Swap in embeddings past a few thousand facts; nothing else has to change.

06

Backends

The brain is swappable. The app never learns which one is running, so changing models is a config line rather than a refactor — which matters, because models turn over every few months and you don't want that churn reaching your code.

BackendCostOfflineSetup
DemofreeyesNone. Scripted replies so the product runs the moment you clone it.
OllamafreeyesInstall, then ollama pull llama3.2. The recommended default.
Groqfree tiernoFree key, no card. Hosted open models, very fast.
Geminifree tiernoFree key from Google AI Studio.
OpenAI-compatiblevariesdependsOne implementation covers LM Studio, vLLM, llama.cpp, OpenRouter, Together and more — they all copied the same wire format.
ClaudepaidnoThe strongest reasoning available, if you want one paid option.
Your own modelfreeyesThe transformer you trained yourself in scratch/. Will produce nonsense — that's the lesson.

Fallback chain

Set more than one and Praxis health-checks them in order. If Ollama is down because you closed the laptop, it moves to Groq and tells you why in a toast rather than failing the turn. An assistant that degrades is a better product than one that dies.

Why tool calling uses text, not the native API

Every provider has its own function-calling format, and most local models have none at all. Praxis uses a text protocol instead — the model emits a call block, Praxis catches it mid-stream and runs it. Native calling is better where it exists; this works identically on Ollama, Groq, Gemini, Claude and a model you trained last Tuesday, which for a project about owning your own AI is the more valuable property.

How it's built

Python and SQLite on the server, plain DOM in the browser. No build step anywhere.

The assistant

praxis/modes.pyTen behavioural overlays
praxis/agent.pyThe loop — compose, recall, stream, intercept, execute
praxis/providers.pySeven backends behind one interface, with fallback
praxis/store.pyConversations, messages and memory in SQLite
praxis/tools/The nine tools, one file each
The product
server.pyThe API — streaming chat, conversations, memory, uploads
web/index.htmlLanding page
web/chat.htmlThe app
web/static/app.jsClient — streaming, markdown, palette, drawers
Understanding it
scratch/model.pyA GPT from zero — attention, MLP, residuals, sampling
scratch/train.pyTrain it on your CPU in about fifteen minutes
finetune/train_lora.pyLoRA on an open model, sized for a free Colab GPU

That last group is the part most personal-AI projects skip. The transformer in scratch/model.py is the same architecture family as GPT-4, Claude and Gemini — not a simplified teaching version. Train it and you get convincing Shakespearean gibberish from 800,000 parameters, which teaches you more about what these systems are than any amount of reading.

09

Running it

It works the moment you clone it, on the demo backend. Giving it a real brain takes two more commands. 

# 1 · install and run — works out of the box
pip install -r requirements.txt
python server.py                  → localhost:8000

# 2 · give it a real brain (free, local, offline)
curl -fsSL https://ollama.com/install.sh | sh
ollama pull llama3.2
echo "PROVIDER=ollama" > .env

# 3 · restart. that's the whole setup.
python server.py                  ✓ ready

Everything else is one file. .env holds the backend, your name, the default mode, which tools are enabled, and the limits. Rename the whole product by changing BRAND_NAME. Your conversations and memory live in data/praxis.db — back it up by copying it.

10

What it isn't

A manual that only lists strengths isn't a manual. These are real, and worth knowing before you rely on it.

It is not a frontier model

Praxis is the scaffolding — identity, memory, tools, interface. The intelligence is whatever backend you point it at. On a 3-billion-parameter local model it will be noticeably less capable than ChatGPT, because it is. That's the honest trade for free and offline.

Tool calling depends on the model

The text protocol works everywhere, but a small model will sometimes forget the syntax or call a tool it didn't need. Larger models follow it reliably. The six-round ceiling exists precisely because small models get stuck in loops.

Memory recall is lexical

Ask about something you described in completely different words and the keyword match may miss it. That is the price of being able to explain why a memory surfaced, and it becomes the wrong trade past a few thousand facts.

Search is scraping by default

DuckDuckGo is free precisely because it isn't an API. If the page layout changes it breaks, and some networks block it. Praxis says so plainly when it fails rather than going quiet — and Brave, Tavily or SearXNG are one config line away.

Single user, no auth

It binds to localhost and has no accounts, no login and no permissions. That is correct for a personal tool on your own machine and completely wrong for anything exposed to a network. Don't put it on the open internet as-is.
